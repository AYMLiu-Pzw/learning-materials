第 1 页 · 理念篇：先搞懂 Linux 的构造，再背命令

1. Shell 是什么？

Shell = 翻译官。你想让电脑做事，但电脑听不懂人话，只听得懂机器码。Shell 就是站在中间翻译的人：你敲 ls，它翻译成"列出这个文件夹里有什么"，再交给系统执行。你打开 Ubuntu 终端看到 liu@ubuntu:~$ 这个提示符，就是 Shell 在等你说。

📌 提示符拆解：liu@ubuntu:~$ → liu=用户名 → @=在 → ubuntu=机器名 → :=分隔 → ~=现在在家目录 → $=普通用户（换成 # 就是管理员 root）。看到这串东西亮起来，说明 Shell 准备好了，等你说。

2. 命令的通用构造（最重要的一条规律）

所有命令都是同一个公式：

命令 [选项] [参数]
ls      -l         /home
动词   副词       宾语（对谁做）
📌 规律①：选项是"怎么干"。一个字母的选项前面一个横线 -l；一个单词的选项前面两个横线 --all。多个单字母选项可合并：ls -l -a = ls -la。
📌 规律②：万能求助。任何命令卡住，先敲 命令 --help 看用法；想细看敲 man 命令（说明书），按 q 退出。

3. 目录树：一切皆文件，文件都有家

/              ← 树根，一切的起点
├── home        ← 家：/home/liu 是你的地盘，你的文件都放这
├── etc         ← 配置：改系统设置来这
├── var/log     ← 日志：排查问题来这（重要！）
├── tmp         ← 临时：放临时文件，重启会清
├── usr         ← 软件：装好的程序住这
└── bin         ← 命令：ls、cd 这些命令本身住这
📌 规律③：路径两种写法。从 / 开始写 = 绝对路径（/home/liu/note.txt）；从当前位置开始写 = 相对路径（note.txt）。两个特殊符号：. = 当前目录，.. = 上一层。

4. 管道哲学：小命令组合成大功能

Linux 设计思想：每个命令只做好一件事，用管道 | 把命令串起来。管道 = 把前一个命令的输出，喂给后一个命令当输入。

ps aux | grep nginx | wc -l
列出所有进程 → 过滤含nginx的行 → 数一数有几行 = "nginx 启动了几个进程"
📌 规律④：重定向把结果存起来。 > 覆盖写入文件， >> 追加到文件末尾。例：ls > list.txt（把列表存进文件）。
📌 规律⑤：通配符。* = 任意一串字符，? = 任意一个字符。例：rm *.log = 删除所有 .log 结尾的文件。

权限速读卡（背 chmod 前先看这张图）

- rwx r-x r-x
│ └┬┘ └┬┘ └┬┘
│  │   │   └── 其他人权限：r-x（可读、可执行）
│  │   └────── 属组权限：r-x
│  └────────── 属主权限：rwx（读、写、执行）
└────────────── 类型：- 文件  d 目录  l 链接
📌 数字速记：读 r = 4，写 w = 2，执行 x = 1。755 = 属主7(4+2+1) + 组5(4+1) + 他人5(4+1)；644 = 属主6(4+2) + 组4 + 他人4。文件最常是644，脚本/程序最常是755。
