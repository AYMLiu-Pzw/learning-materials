## 设计理念

1. **理念篇先行**：每份文档第 1 页先讲「它是什么、怎么构造的、有什么规律」，先理解再记忆
2. **按使用频率排序**：最基础、最高频的内容排在最前，可以按页按组背
3. **颜色贴近真实环境**：命令用终端绿、报错用红、Python 用代码配色，形成视觉记忆
4. **正文/注文分字号**：正文 11.5pt，注释和例文 9.5pt，一眼分清主次
5. **逐词拆解**：每条报错按「逐词 → 整句 → 为什么 → 怎么办」四层讲透

## 打印方法

1. 用 **Chrome 或 Edge** 打开 HTML 文件，按 `Ctrl + P`
2. 纸张 **A4**，边距默认，缩放 100%
3. 如果打印出来没有颜色/底色：更多设置 → 勾选「**背景图形**」

> 在线预览（启用 GitHub Pages 后）：
> `https://<你的用户名>.github.io/<仓库名>/01-linux-commands.html`

## 排版方法

这些 HTML 文件是「为打印而设计」的，用了以下 CSS 分页技术保证版式干净：

| 技术 | CSS | 解决的问题 |
|---|---|---|
| 整块不跨页 | `break-inside: avoid`（表格/报错卡/代码框/规律框） | 一个表格或一条报错不会被拦腰撕开 |
| 标题不落底 | `page-break-after: avoid`（标题） | 小标题不会孤零零留在页尾 |
| 防孤行 | `orphans / widows`（段落） | 分页时每边至少保留几行 |
| 颜色保真 | `print-color-adjust: exact` | 打印时保留颜色和底色 |
| 自然填装 | 不滥用强制分页，块装不下才整体跳页 | 页面利用率高，无大片空白 |
| 定向压缩 | `.tight` / `.xtight`（行距 1.5→1.27，字号不变） | 差几十像素时把某块「挤」回上一页 |
| 精准锚点 | `.pb`（仅在必要时强制另起页） | 避免「标题在本页、表格在下一页」的分家 |

**迭代方法**：排版不是一次猜出来的——用无头浏览器（Edge/Chrome `--headless --dump-dom`）
在打印宽度（A4 内容宽 703px）下实测每个块的真实高度，按每页 1024px（768pt）模拟分页，
发现孤行/分家/空页就调整压缩参数，再实测验证，直到每页填充率都合理。
